## §0 总览 + 共享数据结构

### 0.1 四变体一览

| 变体 | 形态 | 核心机制 | 复用关系 |
|---|---|---|---|
| A 任务链版 | 卡通老师气泡 + POE（预测→操作→验证）任务链 | 每模式 3~5 个小任务，预测题制造认知冲突 | 用 §3 tasks 数据 |
| B 语音版 | TTS 配音 | 进模式播引入语；每步骤/纠错触发对应配音 | 音频 clip id 与 §1/§2 的 step/error id 一一对应（§4），文字稿同一套 |
| C 分步引导版 | 「跟我做」聚光灯 | 高亮下一步该操作的控件 + 聚焦该观察的 canvas 区域，逐步走完知识点 | 用 §5 引导序列 |
| D 字幕解说版（重点） | 屏幕底部「歌词式」字幕条 | 每步交互动作触发老师讲课解说，言简意赅按步推进；做错时字幕条变橙色「不对哟～」 | 用 §1 steps + §2 errors + §7 free 数据 |

**推荐实现路线**：四变体共享同一份 `script.js` 数据（§0.2），仅渲染层不同（A=气泡+选项面板、B=audio 播放、C=高亮遮罩、D=底部字幕条）。可先做 D（蔡总方案），A/B/C 按同一数据切换皮肤，对比给蔡总验收。

### 0.3 引导层私有进度字段 G（不属于实验 core，script 运行时自建）

trigger 表达式中允许引用 `G.*`——这是**引导层自己维护的进度快照**（只读监听 R 与 DOM，绝不写实验状态）：

| G 字段 | 含义 | 采集方式 |
|---|---|---|
| `G.recCount` | 记录表已填行数 | 数 `#rec-table tbody .c-do` 中 `textContent!=='—'` 的行数（core 的 `recFill()` 就是这么判空的） |
| `G.do0` | 进 M1 时的物距快照 | 进模式时记 `R.doCm`（初始 8） |
| `G.objChangeCount` | 物距被改动次数 | 监听 `#obj-slider` input 或 `R.doCm` 变化 |
| `G.eqEverOn` | 本次会话是否开过等效蜡烛 | 监听 `R.eqOn` 曾为 true |
| `G.everMatched` | 是否重合过 | 监听 `R.matched` 曾为 true |
| `G.firstSlotDone` | M3 是否装好过第一面镜 | 监听 `R.m3.top.state==='slot' \|\| R.m3.bottom.state==='slot'` 曾成立 |
| `G.modeEnterT` | 进当前模式的时间戳 | setMode 时记录（供延时序列用） |

## §1 各模式完整步骤解说稿（D 版核心 / B 版文字稿）

格式：`step id | 触发条件（真实R字段） | 解说词（≤25字） | 该步知识点`。触发时机=状态**变为真**时播一次（边沿触发，不循环刷屏）。

### M1 成像探究台（8 步）

建议步骤流：点燃蜡烛 → 观察虚像 → 拖物蜡烛看像对称移动 → 开等效蜡烛 → 拖到与像重合 → 记录数据 → 换物距重复 → 得出结论。

| step id | 触发条件 | 解说词 | 知识点 |
|---|---|---|---|
| m1-s1 | `R.objLit===true && R.eqState==='off' && !G.everMatched` | 点燃啦！火苗亮了，玻璃板里的像才看得清哦。（2026-10-26 蔡总反馈③改：讲点燃的原因） | 点燃使物更亮，像更清晰；玻璃板透光又反光，能同时看到像和板后空间 |
| m1-s2 | `R.objLit && !R.eqOn && G.objChangeCount>=1 && Math.abs(R.doCm-G.do0)>=2 && (G.t-G.lastObjChangeT)<1600`（2026-10-26 蔡总反馈③加拖动新鲜度：只在真的拖动蜡烛时说，点燃瞬间不再抢话） | 蜡烛移远，像也跟着移远，大小可没变哦。 | 像物同步对称移动；像大小与物距无关（explain.html：近大远小只是视角错觉） |
| m1-s3 | `R.eqOn===true && (R.eqState==='tray'\|\|R.eqState==='held')` | 等效蜡烛拿出来了，把它拖到玻璃板后面去。 | 等效替代法：用未点燃的相同蜡烛去找像的位置 |
| m1-s4 | `R.eqState==='placed' && !R.matched && R.eqDo>=0` | 慢慢挪，让它跟板里的像完全重合。 | 重合处就是像的位置 |
| m1-s5 | `R.matched===true && !G.everMatched` | 重合了！像和物等大，到镜面距离也相等。 | 等大、等距（core 判重合容差≤6px，拼成一支完整蜡烛） |
| m1-s6 | `G.recCount===1` | 记下第一组！物距和像距是不是相等呀？ | 记录数据：蜡烛到板距离 vs 像到板距离（教材P99表） |
| m1-s7 | `G.recCount===2` | 换个物距再做一次，规律还成立吗？ | 多做几次避免偶然性 |
| m1-s8 | `G.recCount>=3` | 三组数据都说明：等大、等距、对称、虚像！ | 实验结论四条（explain.html 成像特点） |

### M2 虚像原理（6 步）

建议步骤流：看物点S → 开入射反射线 → 开反向延长线见S′ → 拖眼睛进光束 → 拖光屏到S′承接不到 → 对称标注。

| step id | 触发条件 | 解说词 | 知识点 |
|---|---|---|---|
| m2-s1 | 进入 m2 模式（`R.mode==='m2'`，intro 后延时约2s） | 烛焰上这个亮点叫 S，光从它射向四面八方。 | 物点 S 发光（教材图4.3-3 光路起点） |
| m2-s2 | `R.m2.showRay===true && !G.raySaid`(首次) | 光射到镜面反射出去，反射光进入眼睛。 | 入射-反射光线；眼睛接收反射光 |
| m2-s3 | `R.m2.showExt===true && R.m2.showRay` | 把反射光线反向延长，它们全交在 S′ 一点！ | 反向延长线交点 S′ 就是像（explain.html：眼睛习惯沿直线追溯） |
| m2-s4 | `R.m2.eye.inBeam===true && !G.inBeamSaid`(首次) | 眼睛逆着反射光看去，S′ 的像一下子亮了。 | 眼睛在光束内才能看到虚像；像的亮暗表示可见性 |
| m2-s5 | `R.m2.screenAtSp===true && !G.spSaid`(首次) | 光屏承接不到！S′ 没有光真正到达，是虚像。 | 虚像不能用光屏承接（想想做做，P99） |
| m2-s6 | `R.m2.showSym===true` | 看，S 和 S′ 关于镜面对称，距离相等。 | 对称法作图核心：像物关于镜面对称、连线与镜面垂直 |

### M3 潜望镜（5 步）

建议步骤流：拖镜入槽 → 调45° → 开光路 → 眼睛看到景物。

| step id | 触发条件 | 解说词 | 知识点 |
|---|---|---|---|
| m3-s1 | 进入 m3 模式（intro 后延时约2s） | 潜艇藏在水下，靠潜望镜把光接力送进艇里。 | 潜望镜=平面镜的应用（P101） |
| m3-s2 | `(R.m3.top.state==='slot' \|\| R.m3.bottom.state==='slot') && !G.firstSlotSaid` | 装好一面镜子啦，再把另一面也装进卡槽。 | 潜望镜需要上下两块平面镜 |
| m3-s3 | `R.m3.top.state==='slot' && R.m3.bottom.state==='slot' && !G.bothSlotSaid` | 两面镜子都到位，角度保持 45° 刚刚好。 | 45° 安装（setMode 默认 angle=45，滑杆同步调两面镜） |
| m3-s4 | `R.m3.showPath===true && R.m3.inEye && !G.pathSaid` | 光两次转折，走 Z 字形，水平射向眼睛啦。 | 45° 两次反射、光路两次转折后水平射出 |
| m3-s5 | m3-s4 触发后延时约1.5s（同状态 `R.m3.inEye`，右上角画中画已出现） | 瞧右上角，眼睛看到的是水面小船正立的像！ | 潜望镜成正立的像（render 画中画标注「正立的像」） |

> 注：m3-s5 与 m3-s4 触发状态相同，用引导层延时序列分开播报（先讲光路、再指引看画中画），避免一条字幕塞两个知识点。

## §3 A 版任务链（POE：预测→操作→验证）

每模式 3~5 个任务。预测题专挑**迷思概念**下手（近大远小、虚像能承接、像随距离变小等），先让学生选，再让实验打脸或印证，制造认知冲突。答错不给答案，只引导去操作观察后再选。

### M1（5 任务）

| id | stage | 预测问题 q | options | 验证条件 done | praise（答对） | retry（答错） |
|---|---|---|---|---|---|---|
| m1-t1 | predict | 点燃蜡烛后，玻璃板里的像跟蜡烛比，大小会怎样？ | ①一样大 ②比蜡烛小 ③比蜡烛大 | `R.objLit===true`（点燃后观察） | 对啦！像和物始终等大，记住咯～ | 咦？去点燃蜡烛，仔细比比像和蜡烛的大小再选～ |
| m1-t2 | predict | 把蜡烛往远离玻璃板的方向移，像会变小吗？ | ①会变小 ②不变，还是等大 ③会变大 | `Math.abs(R.doCm-G.do0)>=3`（拖动物蜡烛后观察） | 厉害！远近只改位置不改大小，「近大远小」是错觉～ | 拖蜡烛移远一点，盯着像的大小看，再选一次～ |
| m1-t3 | act | 用等效蜡烛找到像的确切位置！ | —（操作任务，无选项） | `R.matched===true` | 完美重合！这里就是像的位置，等效替代法 get√ | 慢慢挪等效蜡烛，跟板里的像对齐就成功啦～ |

## §6 文案风格红线

1. **长度**：字幕/解说 ≤25 字/条（A 版预测题干与选项除外，但选项也尽量 ≤12 字）；intro ≤60 字。超了就拆两条，不许浓缩成教材长句。
2. **口语化**：像一位亲切的老师站在旁边说话。用「啦/呀/哦/哟/～」，用短句，用第二人称「你」。禁教材腔：禁「综上所述」「由实验可得」「如图所示」；禁书面被动长句。
3. **纠错语气**：活泼不打击。统一「不对哟～」开头（或「别急哟～」），**只说应该先做什么**，不说「你错了」「真笨」，不直接给答案。
4. **物理表述零错误**，口径与 explain.html 完全一致：
   - 虚像：反射光线**反向延长线**的交点 S′；S′ 处**没有光真正到达**，不是实际光线会聚点；**光屏承接不到**。
   - 成像特点：**等大、等距（像距=物距）、像物连线与镜面垂直、关于镜面对称**；四条缺一不可、不可说反。
   - 像的大小**与物距无关**——严禁出现「移远像变小」之类表述当正确结论；「近大远小」只能以「视角错觉」身份出现。
   - 实验方法：**薄玻璃板**（透光+反光，便于定像位）、**两支完全相同的蜡烛**、**等效替代法**、**多做几次避免偶然性**。
   - 潜望镜：**两块平面镜、45° 安装、两次反射（两次转折）、水平射出、正立的像**。
5. **一条字幕一个知识点**：不塞两个概念（m3-s4/s5 拆开就是这个原因）。
6. **触发纪律**：步骤解说边沿触发只播一次（`G.*Said` 标记）；纠错可重复触发但同一条 5s 内不重播；字幕不打断、不阻塞操作，纯伴随。
